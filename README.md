# Area Manager Performance Dashboard — ส้มตำเจ๊แดง

แดชบอร์ดผลงาน Area Manager รายสาขา เทียบ YoY / MoM · หน้าเดียวจบ ใช้ได้ทั้งคอมและมือถือ

- **เว็บ:** GitHub Pages (ไฟล์ HTML ล้วน ไม่ต้อง build)
- **ข้อมูล:** Supabase (Postgres) — โปรเจกต์แยกของแดชบอร์ดนี้เอง ไม่ใช้ร่วมกับระบบอื่น
- **เข้าใช้งาน:** รหัสช่องเดียวเหมือนเดิม ไม่ต้องสร้างบัญชีผู้ใช้ — ฐานข้อมูลเป็นคนตรวจรหัส
- **กราฟ:** Chart.js 4.4.1 (ฝังในไฟล์ ไม่ต้องต่อเน็ตโหลดเพิ่ม)

---

## ไฟล์ในโปรเจกต์

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | ตัวแดชบอร์ดทั้งหมด (HTML + CSS + JS + Chart.js) |
| `config.js` | URL และ key ของ Supabase — **ไฟล์เดียวที่ต้องแก้ตอนติดตั้ง** |
| `supabase/schema.sql` | ตาราง ฟังก์ชันตรวจรหัส และการปิดสิทธิ์ — วางใน SQL Editor แล้ว Run |
| `.nojekyll` | บอก GitHub Pages ไม่ต้องประมวลผลด้วย Jekyll |
| `docs/` | แบบฟอร์ม Excel ตัวอย่างที่ใช้เป็นมาตรฐานการนำเข้า |

## ติดตั้งครั้งแรก

### 1. สร้างโปรเจกต์ Supabase
สร้างโปรเจกต์ใหม่ที่ [supabase.com](https://supabase.com) — **ห้ามใช้ฐานร่วมกับ FAB Operations Hub หรือ Training Record**

### 2. สร้างตาราง
Supabase → **SQL Editor** → วางทั้งไฟล์ [`supabase/schema.sql`](supabase/schema.sql) → **Run**

### 3. ใส่ค่าเชื่อมต่อ
Supabase → **Settings → API** คัดลอก *Project URL* กับ *anon key* มาใส่ใน `config.js`

```js
window.AM_CONFIG = {
  url: 'https://xxxxxxxx.supabase.co',
  key: 'eyJhbGciOi...'
};
```

> key ตัวนี้เปิดเผยได้ตามปกติ — ตารางถูกปิดตายด้วย RLS ไม่มี policy ใครถือ key เฉย ๆ อ่านอะไรไม่ได้
> **ห้ามใส่ `service_role` key เด็ดขาด**

### 4. เข้าเว็บครั้งแรกด้วยรหัสแอดมิน
ใส่รหัสตั้งต้น `ADMIN2026` → หน้าเว็บจะอัปโหลดผัง 5 โซนขึ้นฐานให้เอง

### 5. เปลี่ยนรหัสทันที
ไปแท็บ **จัดการโซน** เปลี่ยนรหัส Admin, VP และรหัสของแต่ละโซนให้เป็นของจริง
รหัสตั้งต้นอยู่ในไฟล์สาธารณะบน GitHub ใครก็เห็น — **ต้องเปลี่ยน**

จากนั้นแจกรหัสของแต่ละโซนให้ AM คนนั้น ๆ จบ ไม่ต้องสร้างบัญชีผู้ใช้

## นำเข้าข้อมูลจากไฟล์ Excel

ไม่ต้องพิมพ์ทีละช่อง — ไปแท็บ **กรอกข้อมูล** แล้วลากไฟล์รายงานประจำเดือนมาวาง (หรือกดเลือกไฟล์)

ยึดตามแบบฟอร์ม **Monthly Area Manager Performance Report** บล็อกกรอกข้อมูล (แถว 107 เป็นต้นไป):

| แถว | คืออะไร |
|---|---|
| 107 | `เดือน (Month) :` — ระบบอ่านเดือนจากช่องนี้ ถ้าเว้นว่างจะเดาจากชื่อชีต แล้วให้เลือกเองในหน้าต่างยืนยัน |
| 109-110 | หัวตาราง 2 ชั้น — ชื่อกลุ่ม แล้ว `2025 / 2026 / YoY %` |
| 111 เป็นต้นไป | ข้อมูลรายสาขา หยุดอ่านเมื่อเจอแถว "รวม (Total)" |
| 129 เป็นต้นไป | บล็อกเดือนก่อนหน้า — Sales / EBIT / COGs / COL / OT / Complaint / Trans Dine In / Ticket Dine In / Trans Del / Ticket Del / OSS % |

คอลัมน์ `B`–`AB` คือ 9 กลุ่ม กลุ่มละ 3 ช่อง · `AC` = OT · `AD` = OSS % · `AE` = Complaint · `AF` = หมายเหตุ
ช่อง YoY % และ COL % ไม่ต้องกรอก เว็บคำนวณให้เอง

ก่อนบันทึกจริงจะมีหน้าต่างสรุปให้ตรวจ: เดือนที่จะลง จำนวนสาขาที่ตรงกัน และรายชื่อสาขาที่เทียบชื่อไม่ได้

- เทียบชื่อสาขาแบบยืดหยุ่น เขียนสั้นว่า `พรานนก` ก็จับคู่กับ `ร้านส้มตำเจ๊แดง (พรานนก)` ได้
- ช่องที่เว้นว่างในไฟล์จะไม่ไปลบข้อมูลเดิมในเว็บ
- บล็อกเดือนก่อนหน้าเติมเฉพาะช่องที่ยังว่าง ไม่เขียนทับของเดิม
- ชื่อสาขาที่คล้ายแต่ไม่ตรง ระบบถามให้ยืนยันทุกครั้ง แล้วจำการจับคู่ไว้ในฐานกลาง ใช้ได้ทุกคนทุกเครื่อง
  (ต้องรัน [`supabase/aliases.sql`](supabase/aliases.sql) ครั้งเดียว ถ้าติดตั้งจาก schema.sql รุ่นก่อนหน้า)
- ผู้ดูแลพื้นที่นำเข้าได้เฉพาะสาขาในโซนตัวเอง สาขานอกโซนจะถูกข้าม

## งบกำไรขาดทุน (แท็บ งบกำไรขาดทุน)

ดูงบ P&L ของเดือนที่เลือก หรือยอดสะสมตั้งแต่ ม.ค. รวมทุกสาขาในขอบเขต หรือเลือกดูทีละสาขา

- การ์ดสรุป: รายได้รวม · กำไรขั้นต้น · กำไรจากการดำเนินงาน · กำไรสุทธิ · ต้นทุนขาย % · ค่าแรง % · ค่าขายและบริหาร % · ค่าเช่า % (เทียบเดือนก่อน)
- กราฟรายได้และกำไรสุทธิรายเดือน และกราฟต้นทุนเป็น % ของรายได้
- ตารางงบตามผังบัญชี กดหัวข้อเพื่อกางบัญชีย่อย เทียบเดือนก่อน
- ตารางกำไรรายสาขา เรียงตามกำไรสุทธิ กดแถวเพื่อดูงบของสาขานั้น
- ผู้ดูแลพื้นที่เห็นเฉพาะสาขาในโซนตัวเอง

**นำเข้า** (เฉพาะ Admin / VP): กดปุ่ม **นำเข้างบ** หรือลากไฟล์ **PL Jaedang ปี** (เช่น `PL Jaedang 2026-(9-9).xlsx`) มาวางที่เดียวกับไฟล์รายงาน ระบบรู้เองว่าเป็นไฟล์งบ

- อ่านจากชีตรายเดือน `JAN` … `DEC` (แถวหัวเป็นรหัสสาขา เช่น `BR002`, `00018`) ทุกเดือนที่มีตัวเลขในไฟล์
- ข้าม สำนักงานใหญ่ (`00000`) · BT-ALL (`BR099`) · ครัวกลาง (`BR001`)
- จับคู่รหัสสาขากับชื่อไทยในเว็บให้เอง ชื่อที่ไม่ตรงเป๊ะจะถามให้ยืนยัน และจำการจับคู่ไว้
- สาขาในงบที่ไม่มีในเว็บ (เช่น สาขาที่ปิดไปแล้ว) ตั้งต้นเป็น **เพิ่มเป็นสาขาปิด** — เก็บไว้ในรายการ "สาขาที่ลบแล้ว / สาขาปิด"
  ในแท็บผู้ดูแลและสาขา ไม่ขึ้นในหน้าอื่นและไม่นับในโซน แต่งบยังรวมในยอด "ทุกพื้นที่" ของแท็บงบ และเลือกดูทีละสาขาได้ (Admin / VP เท่านั้น)
- ไฟล์ต้องเป็นงบปีเดียวกับเว็บ · นำเข้าซ้ำจะแทนที่งบของเดือนที่อยู่ในไฟล์ทั้งชุด ไม่ยุ่งกับตัวเลขในแท็บกรอกข้อมูล
- เก็บในแถวข้อมูลสาขา-เดือนเดิม (`fields.pl`) ไม่ต้องแก้ตารางในฐาน

## สิทธิ์การใช้งาน

ล็อกอินด้วย **รหัสเข้าใช้งานช่องเดียว** ไม่ต้องมีบัญชี/อีเมล

| รหัส | เห็นข้อมูล | กรอกข้อมูล | จัดการโซน/รหัส |
|---|---|---|---|
| Admin | ทุกโซน | ทุกโซน | ได้ |
| VP | ทุกโซน | ทุกโซน | ไม่ได้ |
| รหัสโซน | เฉพาะโซนนั้น | เฉพาะโซนนั้น | ไม่ได้ |

**สิทธิ์บังคับที่ฐานข้อมูล ไม่ใช่แค่ซ่อนบนหน้าจอ** — ตารางทั้งหมดปิดตายด้วย RLS
หน้าเว็บแตะตารางตรง ๆ ไม่ได้เลย ต้องเรียกผ่านฟังก์ชันใน `schema.sql` ซึ่งเอารหัสไปตรวจกับฐานทุกครั้ง
ถือรหัสโซน A ยิง API ตรง ๆ ก็ยังอ่านหรือแก้ข้อมูลโซน B ไม่ได้ และรหัสของโซนอื่นก็ถูกตัดออกก่อนส่งกลับ

ลืมรหัส — ดูได้ใน SQL Editor:

```sql
select value->>'adminCode' as admin, value->>'vpCode' as vp,
       jsonb_path_query_array(value->'zones', '$[*].code') as zone_codes
from public.am_config where key = 'main';
```

## วิธีเก็บข้อมูล

| ตาราง | เก็บอะไร |
|---|---|
| `am_entries` | 1 แถว = 1 สาขา 1 เดือน (`year, month, branch_id, fields`) — แยกรายแถวเพื่อให้หลายโซนกรอกพร้อมกันได้ไม่ทับกัน |
| `am_config` | ผังโซน/สาขา/รหัสเข้าใช้งาน เก็บเป็น jsonb ก้อนเดียว (`key = 'main'`) |
| `am_branches` | สำเนาแบน สาขา → โซน ไว้ให้ฟังก์ชันใช้ตัดสินสิทธิ์ (อัปเดตให้เองเมื่อแอดมินแก้ผัง) |

| ฟังก์ชัน | หน้าที่ |
|---|---|
| `am_auth(code)` | ตรวจรหัส คืน role และโซน |
| `am_get_config(code)` | ผังโซน/สาขา (ตัดรหัสออกถ้าไม่ใช่แอดมิน) |
| `am_fetch(code, year)` | ข้อมูลทั้งปีเฉพาะสาขาที่มีสิทธิ์เห็น |
| `am_touched(code, year)` | เวลาแก้ล่าสุด ใช้เช็คว่ามีคนกรอกเพิ่มไหม |
| `am_upsert(code, year, rows)` | บันทึกหลายสาขาในครั้งเดียว |
| `am_set_config(code, value)` | บันทึกผัง + รหัส (แอดมินเท่านั้น) |

- บันทึกแบบหน่วง 0.7 วินาที ไม่ยิงฐานทุกตัวอักษร
- เน็ตหลุดจะเก็บคิวไว้แล้วลองใหม่ให้เอง
- ดึงของใหม่ให้เองทุก 20 วินาที (ถามแค่ "แก้ล่าสุดเมื่อไร" ก่อน ถ้าไม่มีอะไรเปลี่ยนก็ไม่ดึงข้อมูลจริง)
- `localStorage` ยังทำงานเป็นสำเนาสำรอง และถ้า `config.js` ว่าง หน้าเว็บจะกลับไปโหมดออฟไลน์ให้ใช้งานต่อได้
